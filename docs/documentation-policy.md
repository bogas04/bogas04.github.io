# Documentation policy

Treat documentation as code. The documentation must change with the decision or
behaviour it describes.

- Create or update a narrow document whenever adding a route, feature, or an
  enduring project rule.
- Link that document from `AGENTS.md` when every future agent needs to know it.
- Add route specific visual direction before or alongside implementation.
- Record non obvious constraints, compatibility promises, and rejected options
  that should not be rediscovered later.
- Keep documents small, focused, easy to review, and easy to delete if the
  related feature disappears.

Do not put a permanent rule only in a pull request description, commit message,
or chat conversation.
